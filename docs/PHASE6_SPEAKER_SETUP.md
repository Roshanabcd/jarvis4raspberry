# JARVIS OS — Phase 6 Physical Speaker & Playback Engineering

**PipeWire Audio Routing, Test Tone Generation, and Ducking Preservation**

---

## 1. Physical Audio Output Discovery

The user's USB-powered speaker is connected to the ReSpeaker Lite analog 3.5mm DAC:

```text
ALSA Playback: card 2: Lite [ReSpeaker Lite], device 0: USB Audio
PipeWire Sink: Node 54 [ReSpeaker Lite Analog Stereo] (Default Sink *)
Default Volume: 0.65 (65%)
```

---

## 2. Playback Pipeline (`pw-play`)

Audio files generated by OmniVoice (WAV) or Edge-TTS (MP3) are played directly to the default sink via `pw-play`:

```bash
pw-play /home/roshan/.gemini/antigravity/scratch/jarvis-os/data/audio_stage/<audio_id>.mp3
```

### Key Architectural Safeguards:
1. **Asynchronous Execution:** System audio playback runs in a dedicated daemon thread. The AI text response is displayed immediately in the chat interface without waiting for audio generation or playback.
2. **Master Volume Lock:** JARVIS never modifies the master sink volume (`0.65`).
3. **External Audio Stream Preservation (`AudioStreamManager`):**
   - When JARVIS speaks, active media player streams (such as FreeTube, VLC, or browser media) are temporarily ducked to 20% volume.
   - When JARVIS finishes speaking, active streams are automatically restored to their previous volume.
   - External audio processes are never terminated or killed.
4. **Instant Interruption (Barge-In):** When the user speaks the wake word or clicks **Interrupt Audio**, any currently active `pw-play` subprocess is terminated within <10ms.
