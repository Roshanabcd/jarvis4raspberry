# JARVIS OS — Phase 1 Architecture Specification

## 1. High-Level Architectural Overview

Phase 1 establishes a production-grade, provider-independent conversational AI foundation for JARVIS OS running on a Raspberry Pi 5 (8 GB RAM, Debian 13 Trixie, ARM64).

The system replaces legacy hardcoded responses with real neural model inference, truthful hardware telemetry, deterministic tool evaluation, and structured compound multi-task orchestration.

## 2. Component Directory & Responsibilities

| Subsystem | Module | Role & Guarantees |
|---|---|---|
| **Brain Orchestrator** | `ai/brain.py` | Central AI orchestrator; session isolation; provider selection; fastpath dispatch. |
| **Multi-Task Orchestrator** | `ai/agents/task_orchestrator.py` | Decomposes compound requests into distinct tasks; coordinates execution; merges into one report. |
| **Edge Fast-Path** | `ai/local_engine.py` | Rule-based intent classifier; protects coding requests from hardware hijacking; handles standalone numbers. |
| **Tool Registry** | `tools/registry.py` | Central repository of 78 validated tools with schema checks, permission levels, and audit logging. |
| **Deterministic Math** | `tools/calculator/calculator_tools.py` | AST-based mathematical evaluator handling both symbolic math and natural language terms without eval(). |
| **System Telemetry** | `hardware/raspberry_pi/rpi_info.py` | Real Linux hardware metrics from `/proc/uptime`, `/sys/class/thermal`, and `psutil`. |
| **Date & Time Tools** | `tools/datetime/datetime_tools.py` | True system clock and timezone metrics using `datetime.now().astimezone()`. |
| **Session Memory** | `memory/long_term/database.py` | SQLite WAL-mode persistence storing user/assistant turns, request IDs, and status. |
| **Audio Output** | `apps/voice/speech_manager.py` | Asynchronous speech staging and PipeWire system playback without blocking text response generation. |

## 3. Request Lifecycle & Text-First Invariant

1. **Ingress:** Incoming requests receive a cryptographically unique `request_id` (`req_<hex>`) and `message_id` (`msg_<hex>`).
2. **Session Context:** The active session's conversation history is hydrated from SQLite `conversation_messages`.
3. **Execution Routing:**
   - Compound queries (e.g. *RAM + calculation + code*) route to `CompoundTaskOrchestrator`.
   - Conversational recall (*"What was my first question?"*) directly queries session history.
   - Deterministic hardware and arithmetic tasks run via `LocalIntelligenceEngine` (< 5ms).
   - Conversational reasoning, explanations, and coding run via Ollama (`llama3.2:1b`).
4. **Exact Response Preservation:** Output generated by the language model is never truncated, summarized, or overwritten by tool results.
5. **Immediate Delivery:** Displayed text never waits for TTS audio synthesis. Speech staging is strictly asynchronous and opt-in via `speak: true`.
6. **Persistence:** Responses are committed to `jarvis_memory.db` before completion.
